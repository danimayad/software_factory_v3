# Requirements: guide

This folder says what the product must do. It is written with Daniel.

It can be one document or several. What usually belongs here (a reminder, not a form;
add, drop or merge as the project needs):

- **Functional requirements:** what the product does, as a list of features. A feature
  is one capability the user can see and use.
- **Acceptance criteria:** for each feature, how it is judged finished.
- **UX/UI specification:** screens, panels, visual and interactive behavior, when the
  product has a user interface.
- **Non-functional requirements:** qualities such as performance, security, and where
  the product runs.

Detail is in proportion to difficulty: more where a mistake would be costly, less
where the builder's judgment is enough. State what was decided as decided, and an idea
or preference as such.
